How to use this prompt book

This book has one section per task. Work through them in order. Each section gives you:

1.  Cursor prompt  — Copy it exactly into Cursor / Antigravity. Do not paraphrase.
2.  Verification checklist  — Tick each item. Do not move on until all are green.
3.  Common errors  — If something breaks, check this table first.
4.  Git commits  — Run these as soon as verification passes. Every 20–30 min, no exceptions.
5.  Tell teammates  — Send the message verbatim in the group chat.

Non-negotiable rules from the playbook
Git commits every 20–30 minutes. No exceptions. Your history is being watched.
Never commit directly to main. Your branch: feat/rishi-webhook.
One big commit = auto-fail. Small, incremental commits only.
Phase checkpoints are mandatory. All four must verify before moving to next phase.
GPU inference runs on Aryan and Ajinkya only. You consume their outputs — you don't run models.
When something breaks: isolate, announce, diagnose, tag working state, fix minimally. Never panic-refactor.

Your role in the pipeline
You are the assembler and publisher. You consume outputs from other agents and publish them to GitHub. You do NOT own: LangGraph, LLM inference, AST parsing, Docker sandbox, or test execution.

Your integration points:
Ajinkya feeds you: LangGraph state transitions, root_cause, patch_diff, mermaid_diagram, confidence_score
Aryan feeds you: confidence_score, files_changed from cross-file propagation
Ajaya feeds you: tests_passed (True/False gate), regression_test_file content
You publish to: GitHub PRs, /api/status endpoint, React dashboard

1.1  FastAPI Webhook Receiver
Build the async FastAPI server that receives GitHub Actions CI failure events. Validate HMAC signatures, parse the payload, and push parsed events to an asyncio queue for Ajinkya's Orchestrator.

Prompt for Cursor / Antigravity
Copy & paste this prompt exactly
Build a FastAPI webhook receiver in /api/webhook.py with these requirements:

1. Single POST endpoint at /webhook
2. Validate X-Hub-Signature-256 header using HMAC-SHA256 against
   env var GITHUB_WEBHOOK_SECRET — return 403 if invalid
3. Parse the GitHub Actions CI failure payload and extract:
   repository.full_name, head_commit.id,
   check_run.output.text (failure log)
4. Push a dict with keys repo_full_name, commit_sha, failure_log
   to a module-level asyncio.Queue(maxsize=10)
5. Log dropped events if the queue is full
6. The endpoint must be async and non-blocking

Also create /api/main.py that runs the FastAPI app with uvicorn on
port 8000, and add GET /health returning {"status": "ok"}.
Use python-dotenv to load GITHUB_WEBHOOK_SECRET from .env.

Verification checklist
Tick each item before moving on
  □  FastAPI server starts without errors (uvicorn api.main:app --reload)
  □  Pushing a commit to demo repo triggers the webhook — failure log prints in terminal
  □  Invalid signature requests return 403, not 200
  □  Parsed event dict contains: repo_full_name, commit_sha, failure_log

Common errors & fixes
Error
Fix
Webhook signature validation fails for all requests
GITHUB_WEBHOOK_SECRET must match exactly what is on GitHub webhook settings page — no trailing spaces or newlines.
FastAPI returns 422 on webhook POST
Set Content-Type: application/json in the GitHub webhook config page.
Webhook not reaching local machine
Run: ngrok http 8000. Update webhook URL on GitHub to the ngrok HTTPS URL. Keep ngrok running all session.
Queue fills up during testing
Queue has maxsize=10 — this is fine. Dropped events are logged. Move on.
